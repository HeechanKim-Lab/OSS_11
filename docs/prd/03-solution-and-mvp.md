# 03. 솔루션과 MVP

| 제품 | 버전 | 최종 수정 | 관련 가설 |
|---|---|---|---|
| AmpliconSight | 0.2 | 2026-11-12 | H2, H3 |

> v0.2 변경 (`Cycle 1` 반영): 거절 사유 1위("음성대조군에서 어떤 ASV가 왜 제거되는지 근거가 안 보임") 및 2위("R1/R2 오타 자동 치환 필요")를 반영해 **"NTC 오염 ASV 제거 근거 한 줄 툴팁 및 R1/R2 자동 치환 버튼 (`FR8`)"**을 `MS1` `In`으로 추가함 (`H2` 연결).

## 1. 솔루션 개요

- 고유 가치 제안: **원시 FASTQ 업로드 없이 브라우저에서 3초 만에 16S 매니페스트 오류와 오염균 기준을 진단하고, 한 번에 돌아가는 파이프라인 실행 명령어를 받는다.**
- 핵심 사용 흐름 (4단계): Casava 1.8 매니페스트 및 기초 수율 붙여넣기 → Pre-flight QC 진단(R1/R2 짝 오류·트리밍 수율·음성대조군 오염비) 확인 → 추천 파라미터(`FF_ADAPTIVE_DECONTAM` 등) **"수락"** 클릭 → 생성된 `run_pipeline.sh` CLI 스니펫을 복사해 실행
- 현재 대안 대비 차별점: 수십 GB의 FASTQ를 클라우드에 올리지 않는 **Zero-Upload 클라이언트 사이드 검증**이므로 대기 시간이 0초이고 연구 보안 규정을 100% 준수한다.

## 2. MVP 유형과 선택 이유

- 유형: **Wizard of Oz + Single-feature Hybrid** (MS0) → **Automated Single-feature Workbench** (MS1~MS2)
- 선택 이유:
  1. 가장 위험한 가설 `H2`("연구자가 워크벤치의 Pre-flight QC 추천 파라미터를 수락해 실행한다")는 백엔드 클라우드 연산이 아니라 **진단 결과에 대한 연구자의 신뢰와 수용 행동**을 검증하는 것이다.
  2. MS0에서는 정적 웹 워크벤치(`web/index.html`)에서 매니페스트 포맷 검증을 즉시 보여주고, 연구자별 세부 오염 제거(Decontam)·LinDA 파라미터 추천 카드는 본인이 연구실 기준값(`amplicon_platform/core.py`)으로 10분 내에 검수·제시하는 방식이 구축 비용을 2일로 줄여준다.
  3. 단순 랜딩 페이지나 비디오 MVP를 기각한 이유: 연구자는 **자기 샘플의 매니페스트를 실제로 넣어보고 에러가 잡히는 순간**에만 행동을 바꾸므로 최소 동작 검증 화면이 필수적이다.
- 마일스톤별 진화: MS0 (매니페스트 즉시 검증 + WoZ 추천 카드) → MS1 (순수 함수 엔진 연동 + 3D PCoA Feature Flag 자동화) → MS2 (교육용/코호트 프리셋 온보딩) → MS3 (QC 인증 배지·리포트 공유 카드)

## 3. MVP 범위 (In / Out)

| 기능 | In/Out | 검증 가설 | 비고 |
|---|---|---|---|
| Casava 1.8 Paired-end 매니페스트 입력 및 R1/R2 행 단위 검증 | In | H2 | 핵심 입력값. `validate_fastq_manifest` 엔진 연동 |
| Pre-flight QC 진단 및 추천 파라미터 카드 (Cutadapt 수율·Decontam 임계값) | In | H2 | MS0: WoZ 검수 병행, MS1: 완전 자동화 |
| NTC 오염 ASV 제거 근거 한 줄 툴팁 및 R1/R2 오타 원클릭 자동 치환 버튼 (FR8) | In (MS1부터) | H2 | v0.2 추가 (`Cycle 1` 거절 사유 81.8% 해소용 신뢰 장치) |
| 추천 파라미터 "수락(스니펫 생성)" / "직접 수정(거절)" 버튼 | In | — | 측정 장치 — `M2` 수락률의 분자·분모 산출에 필수 |
|Feature Flag 기반 3D PCoA 프리뷰 및 적응형 Decontam 토글 (`FF_INTERACTIVE_3D_PCOA`, `FF_ADAPTIVE_DECONTAM`) | In | H3 | MS1 코호트 재방문 유인 및 Variant A/B 비교 실험용 |
| 연구자 식별용 경량 세션 ID (`researcher_id` 해시 버킷) | In | — | 최소 동작 조건 — 결정론적 SHA-256 A/B 할당 및 코호트 추적 |
| 분석 이벤트 7종 로깅 (`05-metrics.md` §4) | In | — | 측정 장치 — JSONL 및 대시보드 집계 |
| QC 인증 배지 및 마크다운 리포트 공유 링크 생성 | Out (MS3 In) | H4 | 성장 가설(`H4`)은 `H2`·`H3` 검증 통과 후 MS3에서 구현 |
| 원시 FASTQ(수십 GB) 클라우드 업로드 및 서버 DADA2 연산 | Out | — | 클라우드 비용 과다 및 공공기관 보안 위배. Pre-flight QC + 로컬 CLI 브리지로 대체 |
| 고해상도 600 DPI TIFF 논문 투고용 그래프 렌더러 | Out | — | 페르소나 P02 요청사항이나 `H1`~`H4` 중 어떤 가설도 검증하지 않음. MS2 이후 재검토 |
| Illumina `SampleSheet.csv` 자동 변환기 | Out | — | 코어 퍼실리티 세그먼트 Pivot(`P2`) 발생 시에만 In으로 전환 |
| 다중 배치(Batch Effect) 공변량 보정 UI | Out | — | 고급 통계 옵션으로 초기 온보딩 복잡도 증가. PMF 이후 검토 |

구축 기간 추정 (1인, 주 20h): MS0 핵심 화면 및 검증 로직 **2일**, MS1 Feature Flag·자동 스니펫·E2E 테스트 **4일** — 합계 6 영업일로 상한(10 영업일) 이내.

## 4. MVP 성공 기준

`05-metrics.md` 목표치와 동일:

- **MS0 (`H2`, `H1`)**: **M2** Pre-flight QC 추천 수락률 ≥ **60%** (추천 노출 60건 이상, 5일 이상 운영) 및 **M1** 인터뷰 문제 확인율 ≥ **70%** ($N=10$)
- **MS1 (`H3`)**: **M3** D14 코호트 리텐션 ≥ **50%** (가입 코호트 20명 이상) · Guardrail **G1** 첫 QC 완료 시간 중앙값 ≤ **5.0분**, **G2** 파이프라인 첫 실행 성공률 ≥ **85%**

실패 기준: **M2** < **35%** → `10-risks-and-pivot.md` **P1** (Zoom-in) 검토 · **M3** < **30%** → **P3** (Zoom-out) 검토. 그 사이 구간은 회색 지대로서 `06-experiment-plan.md` §3 규칙을 따른다.
