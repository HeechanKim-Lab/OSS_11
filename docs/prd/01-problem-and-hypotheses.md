# 01. 문제와 가설

| 제품 | 버전 | 최종 수정 | 관련 가설 |
|---|---|---|---|
| AmpliconSight | 0.1 | 2026-11-01 | H1~H4 |

## 1. 문제 정의

- 누가: 16S rRNA 앰플리콘 시퀀싱(Micro-Tom 토마토 근권 등 농생명·환경 마이크로바이옴)을 수행하는 Wet-lab 대학원생 및 초기 바이오인포매틱스 연구자 (배치당 24~96개 샘플 처리)
- 언제/상황: 시퀀싱 코어 퍼실리티로부터 Raw FASTQ 파일 수십 개를 수령한 직후, QIIME2/Cutadapt/DADA2/LinDA 파이프라인(`run_pipeline.sh`)을 실행하기 전 매니페스트(Manifest)와 트리밍·오염제거 파라미터를 준비하는 순간
- 무엇이 고통인가:
  1. **사소한 포맷 오류로 인한 수 시간의 대기 낭비**: Casava 1.8 Paired-end 파일명(`_R1_001.fastq.gz` vs `_R2_001.fastq.gz`) 오타나 샘플 ID 중복을 모른 채 서버에 작업을 올렸다가 2~3시간 뒤 에러로 중단됨
  2. **음성대조군(NTC) 오염(Kitome) 판별 기준의 모호성**: 저바이오매스 근권 시료에서 `decontam` 임계값을 얼마로 잡아야 할지 몰라 오염 ASV(`Ralstonia` 등)가 최종 다양성·LinDA 통계에 섞여 들어감
  3. **정적 스크립트 파라미터 튜닝의 결정 피로**: 매 배치마다 트리밍 수율과 3D PCoA 군집 분리도를 확인하기 위해 R/CLI 스크립트를 수동으로 고쳐 돌리는 데 반나절 이상 소모됨
- 근거: 본 연구실 과거 11회 파이프라인 실행 로그(`amplicon_logs/01`~`11`) 및 과제 10의 10명 다중 페르소나 시나리오 평가(`P01`~`P10`)에서 CLI 초보·중급 연구자 대다수가 "서버 실행 전 브라우저에서 3초 만에 매니페스트와 오염 기준을 잡아주는 Pre-flight QC 도구가 절실하다"고 응답함.

## 2. 현재 대안과 한계

| 현재 대안 | 어떻게 쓰는가 | 한계 |
|---|---|---|
| Excel / 수동 텍스트 편집기 | FASTQ 파일 목록을 복사해 수동으로 `manifest.tsv` 작성 | R1/R2 짝 불일치나 공백·한글 경로 오류를 실행 전까지 전혀 잡아내지 못함 |
| QIIME2 CLI 직접 실행 (`qiime tools import`) | Conda 환경 활성화 후 대용량 `.qza` 아카이브 생성 시도로 오류 확인 | 수십 GB 압축·검증에 30분~2시간 소요. 에러 메시지가 비전공자에게 난해함 |
| RStudio (`phyloseq` / `decontam` 스크립트 수동 실행) | DADA2 완료 후 R에서 수동으로 오염 비율과 2D PCoA 플롯 확인 | 사전(Pre-flight) 단계에서는 확인 불가. PC3 축 회전이나 실시간 임계값 비교가 번거로움 |
| 상용 클라우드 플랫폼 (BaseSpace, EzBioCloud) | 웹에 Raw FASTQ 전체를 업로드해 자동 분석 | 대용량 FASTQ 업로드에 수 시간 소요, 유료 과금 부담, 공공 연구과제 미발표 데이터 외부 업로드 보안 규정 위반 |

공통 한계: **"무거운 본 파이프라인을 돌리기 전에, 원시 파일 업로드 없이 3초 만에 실패 원인과 최적 파라미터를 정해주는 Pre-flight 단계"**가 비어 있다.

## 3. 가설 목록

형식: "우리는 **[고객]**이 **[상황]**에서 **[행동]**할 것이라고 믿는다. **[M#]**가 **[목표]**이면 참이다."

| ID | 유형 | 가설 문장 | 검증 지표 | 불확실성 (1~5) | 치명도 (1~5) | 점수 | 우선순위 |
|---|---|---|---|---|---|---|---|
| H1 | 가치 (문제) | 우리는 **16S 앰플리콘 시퀀싱을 수행하는 대학원생·연구원**이 **파이프라인 실행 직전** **매니페스트 포맷 오류와 오염 제거 기준 설정 때문에 최근 3개월 내 2회 이상 재실행 지연을 겪었다**고 믿는다. **M1** 인터뷰 문제 확인율이 **70% 이상**이면 참이다. | M1 | 2 | 5 | 10 | 3 |
| H2 | 가치 (솔루션) | 우리는 **같은 연구자**가 **매니페스트와 기초 수율 정보를 입력한 뒤** **AmpliconSight가 제시한 Pre-flight QC 진단 및 추천 파이프라인 파라미터(`run_pipeline.sh` 스니펫)를 수락해 실행할 것**이라고 믿는다. **M2** Pre-flight QC 추천 수락률이 **60% 이상**이면 참이다. | M2 | 4 | 5 | 20 | 1 |
| H3 | 가치 (리텐션) | 우리는 **Pre-flight QC와 대화형 3D PCoA 프리뷰를 사용한 연구자**가 **2주 뒤 후속 배치 분석에서도** **수동 스크립트 대신 워크벤치로 다시 돌아올 것**이라고 믿는다. **M3** D14 코호트 리텐션이 **50% 이상**이면 참이다. | M3 | 3 | 4 | 12 | 2 |
| H4 | 성장 (바이럴) | 우리는 **Pre-flight QC를 통과한 연구자**가 **연구실 주간 미팅이나 코어 퍼실리티 의뢰 시 'QC 인증 리포트 링크'를 공유**해 동료 연구자를 유입시킬 것이라고 믿는다. **M5** 리포트 공유율 **20% 이상**, K-factor **0.25 이상**이면 참이다. | M5 | 4 | 2 | 8 | 4 |

점수 산정 근거:
- **H1 (10점)**: 불확실성 2 — 연구실 내부 로그(`amplicon_logs/`)에서 이미 반복 확인된 고통이나 타 연구실 표본에서도 동일한지 MS0에서 10명 인터뷰로 재확인. 치명도 5 — 문제가 없으면 제품 존재 이유 없음.
- **H2 (20점, 1순위)**: 불확실성 4 — 연구자들이 자신의 기존 R/CLI 습관을 바꾸어 웹 워크벤치의 추천 파라미터를 실제로 신뢰·수락할지는 검증된 바 없음. 치명도 5 — 핵심 가치 제안 자체.
- **H3 (12점, 2순위)**: 불확실성 3 — 시퀀싱 배치 주기에 맞춰 반복 재방문할지 미지수. 치명도 4 — 일회성 체험에 그치면 지속 불가능.
- **H4 (8점, 4순위)**: 불확실성 4 — 연구자 집단의 리포트 공유 행동 미검증. 치명도 2 — 실패 시 코어 퍼실리티 직접 제휴 채널로 우회 가능.

## 4. 가장 위험한 가정 순위

1. **H2** (20점) → **MS0**에서 Wizard of Oz + 단일 화면 Pre-flight 워크벤치로 최우선 검증. 실패 시 **P1** (Zoom-in: UI 없이 순수 CLI 명령어 생성기로 축소) 검토.
2. **H3** (12점) → **MS1~MS2**에서 Feature Flag(`FF_INTERACTIVE_3D_PCOA`, `FF_ADAPTIVE_DECONTAM`) 자동화 후 2주 코호트 리텐션으로 검증. 실패 시 **P3** (Zoom-out: 기존 QIIME2/R 패키지 내부 플러그인으로 전환) 검토.
3. **H1** (10점) → **MS0** 기간 중 연구자 10명 심층 인터뷰(`E2`)로 병행 확인. 실패 시 **P2** (Customer Segment: 개인 연구자에서 시퀀싱 코어 퍼실리티 매니저 B2B로 전환) 검토.
4. **H4** (8점) → **MS3**에서 QC 인증 카드 공유 실험(`E4`). 실패 시 학회 워크숍·코어 퍼실리티 안내문 채널로 전환.
