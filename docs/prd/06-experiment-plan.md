# 06. 실험 계획

| 제품 | 버전 | 최종 수정 | 관련 가설 |
|---|---|---|---|
| AmpliconSight | 0.2 | 2026-11-12 | H1~H4 |

## 1. 실험 우선순위

| 실험 | 가설 | 점수 (01 §3) | 마일스톤 | 상태 |
|---|---|---|---|---|
| E1 | H2 (Pre-flight QC 추천 파라미터 수락) | 20 | MS0 | 완료 — Cycle 1 통과 (`11-bml-log.md`) |
| E2 | H1 (매니페스트·오염 기준 재실행 고통 존재) | 10 | MS0 (E1과 병행) | 완료 — Cycle 1 통과 |
| E3 | H3 (3D PCoA · 적응형 Decontam 기반 D14 리텐션) | 12 | MS1~MS2 | 진행 중 |
| E4 | H4 (QC 인증 리포트 공유 바이럴) | 8 | MS3 | 계획 |

`E2`(`H1`)를 점수가 더 높은 `E3`보다 먼저 `MS0`에 배치한 이유: 첫 10명 초대 시 15분 인터뷰로 추가 개발 비용 없이 즉시 확인 가능하며, 문제 가설(`H1`)이 기각되면 `E1`·`E3`의 해석 자체가 무의미해지기 때문이다.

## 2. 실험 설계

### E1 — H2 검증 (Wizard of Oz + Pre-flight QC 워크벤치)

- **Build**: `web/index.html`에 Casava 1.8 매니페스트 입력창, 실시간 R1/R2 검증 결과, Pre-flight QC 추천 카드 및 "추천 수락(스니펫 복사)" / "직접 수정(거절)" 버튼 구현 (소요 2일). MS0 동안 연구자별 특수 오염균(`Ralstonia` 등) 임계값 추천 사유는 본인이 연구실 기준(`amplicon_platform/core.py`)으로 검수해 제공.
- **Measure**: 지표 **M2** (`qc_recommendation_accepted` / `qc_recommendation_shown`) 및 Guardrail **G1**(완료 시간), **G2**(첫 실행 성공률). 샘플: 연구자 14명 × 5 영업일 동안 배치/연습 세션 총 노출 **60건 이상** (`experiments/cycle-1/woz-log.csv`). 정성: 거절 클릭 시 이유 선택 및 5일 차 10명 페르소나 심층 피드백 수집.
- **Learn**: **M2 ≥ 60%**이면 `H2` 참으로 판정하고 `MS1` 완전 자동화 착수. **M2 < 35%**이면 거절 사유를 분석해 UI 복잡도 문제일 경우 **P1**(순수 CLI 스니펫 생성기로 Zoom-in) 피벗 검토.
- GitHub Issue: `#35` (`[EXP-001]`)

### E2 — H1 검증 (10명 다중 페르소나 심층 인터뷰 및 시나리오 평가)

- **Build**: `02-target-customer.md` §3의 3대 핵심 질문지 및 시나리오 평가 스크립트(`scripts/run_persona_ab_simulation.py`). 소요 1일.
- **Measure**: 지표 **M1** — 10명의 연구자(`P01`~`P10`) 중 최근 3개월 내 매니페스트 포맷 또는 오염 기준 문제로 2회 이상 파이프라인 재실행을 겪은 비율 (`experiments/persona_feedback_10_users.json`).
- **Learn**: **M1 ≥ 70%**이면 `H1` 유지. **M1 < 40%**이면 개인 대학원생 대신 시퀀싱 코어 퍼실리티 매니저를 타깃으로 하는 **P2**(Customer Segment Pivot) 검토.
- GitHub Issue: `#35`

### E3 — H3 검증 (Feature Flag 기반 2주 A/B 코호트 리텐션 비교)

- **Build**: `amplicon_platform/feature_flags.py`의 결정론적 SHA-256 해시 버킷(`assign_ab_variant`)으로 `Variant A`(정적 테이블 로그)와 `Variant B`(`FF_INTERACTIVE_3D_PCOA` + `FF_ADAPTIVE_DECONTAM` + 원클릭 매니페스트 검증)를 50:50 할당. 소요 4일.
- **Measure**: 지표 **M3** — 2주(14일) 운영 데이터(`experiments/ab_test_2weeks_data.csv`)에서 가입 코호트 20명 이상의 D14 리텐션 및 Activation Rate 비교.
- **Learn**: **M3 ≥ 50%**이면 `H3` 통과, `MS2`에서 프리셋 온보딩으로 확장. **M3 < 30%**이면 독립 웹 워크벤치 형태를 버리고 기존 QIIME2/Snakemake CLI 내부 플러그인으로 들어가는 **P3**(Zoom-out Pivot) 검토.
- GitHub Issue: `#21`, `#35`

### E4 — H4 검증 (QC 인증 리포트 공유 실험)

- **Build**: Pre-flight QC 통과 시 연구실 미팅 발표자료나 논문 보충자료에 붙일 수 있는 "AmpliconSight QC Verified" 배지 및 고유 URL 생성 기능 (소요 3일).
- **Measure**: 지표 **M5** — 주간 활성 연구자 중 공유 링크 생성 비율(`qc_badge_shared`) 및 공유 링크를 통한 신규 연구자 전환율(K-factor). 기간 2주.
- **Learn**: **공유율 ≥ 20% & K ≥ 0.25** 달성 시 바이럴 성장 엔진 확정. 미달 시 코어 퍼실리티 납품 안내문 기본 탑재 채널로 전환.
- GitHub Issue: `#24`

## 3. 판단 기준

모든 수치는 `05-metrics.md` §2의 목표치와 정확히 일치한다.

| 실험 | 지표 | 통과 ≥ | 실패 < | 회색 지대 처리 |
|---|---|---|---|---|
| E1 | M2 Pre-flight QC 추천 수락률 | 60% | 35% | 35~60%: 거절 사유 1위(예: 임계값 산정 근거 설명 부족)를 보완해 추천 사유 툴팁 추가 후 1사이클 재실험. 2회 연속 회색 지대면 P1 |
| E2 | M1 인터뷰 문제 확인율 | 70% | 40% | 40~70%: 대상을 CLI 중급자에서 Wet-lab 석사 1년차 세그먼트로 좁혀 5명 추가 인터뷰 수행 |
| E3 | M3 D14 코호트 리텐션 | 50% | 30% | 30~50%: 미재방문 연구자 5명 인터뷰 후 CLI 자동 생성 스니펫 및 교육용 프리셋 보강 1사이클 수행. 2회 연속이면 P3 |
| E4 | M5 리포트 공유율 / K-factor | 20% / 0.25 | 8% / 0.08 | 8~20%: PI 보고용 1페이지 요약 포맷으로 배지 디자인 변경 후 A/B 1회 재시도 |

전 실험 공통 Guardrail: **G1** 첫 QC 완료 시간 중앙값 > **5.0분** 또는 **G2** 첫 실행 성공률 < **85%** 발생 시 통과 판정을 보류하고 UI/스크립트 버그를 즉시 수정한다.
