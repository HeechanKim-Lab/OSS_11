# 구조화된 코드 리뷰 가이드 (Structured Code Review Guide)

본 문서는 `OSS_11 (AmpliconSight)` 프로젝트에서 코드 리뷰의 효율성과 심리적 안전감을 동시에 확보하기 위한 **`[MUST]` / `[SHOULD]` 태그 기반 피드백 표준**을 정의합니다.

---

## 1. 리뷰 코멘트 태그 체계

리뷰어는 모든 인라인 코멘트 및 종합 리뷰에 아래 4가지 태그 중 하나를 명시합니다.

| 태그 | 구속력 | 의미 및 적용 기준 | 작성 예시 |
| :---: | :---: | :--- | :--- |
| **`[MUST]`** | **필수 (Blocking)** | 머지 전 반드시 해결되어야 하는 문제.<br>- 버그, 예외 미처리, 보안 취약점<br>- 테스트 커버리지(80%) 미달<br>- 결정론적 해싱(A/B 테스트) 일관성 위반 | `[MUST] 입력 read count가 0일 때 ZeroDivisionError가 발생할 수 있습니다. 방어 로직과 단위 테스트를 추가해 주세요.` |
| **`[SHOULD]`** | **권장 (Non-blocking)** | 코드 품질이나 성능을 크게 높일 수 있는 권장 사항.<br>- 알고리즘 복잡도 개선, 캐싱 도입<br>- 함수 분리 및 타입 힌트 보강 | `[SHOULD] 현재 리스트 컴프리헨션 대신 제너레이터를 사용하면 대용량 FASTQ 매니페스트 처리 시 메모리를 절약할 수 있습니다.` |
| **`[NIT]`** | **사소함 (Optional)** | 사소한 스타일, 주석 오타, 네이밍 선호도 차이. | `[NIT] 변수명 d_val 보다 shannon_index가 의미를 더 명확히 전달할 것 같습니다.` |
| **`[PRAISE]`** | **칭찬 (Positive)** | 모범적인 TDD 테스트 케이스, 깔끔한 추상화 등에 대한 격려. | `[PRAISE] SHA-256 해시 모듈로 연산으로 A/B Variant 할당 일관성을 보장한 부분이 매우 깔끔합니다!` |

---

## 2. SLA (Service Level Agreement) 기준

- **첫 응답 SLA**: PR 생성 후 **24시간 이내** 자동 분류 및 1차 리뷰 착수
- **최종 리뷰 완료 SLA**: PR 생성 후 **72시간 이내** 승인(Approve) 또는 수정 요청(Request Changes) 완료
- `.github/workflows/issue_pr_sla_automation.yml` 워크플로우가 SLA 준수 여부를 자동으로 추적하고 주간 요약 리포트를 생성합니다.
